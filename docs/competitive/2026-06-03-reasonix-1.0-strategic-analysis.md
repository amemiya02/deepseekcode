## 执行摘要

1. **Reasonix 1.0 的本质变化是「从窄到宽」。** 0.x（TypeScript）时代它和我们一样是个终端 agent；1.0 用 Go 重写后，它变成了一个**功能面接近 Claude Code 的完整产品**：单二进制、多 provider（DeepSeek/MiMo/原生 Anthropic）、CodeGraph 代码图、对话分支/检查点、Skills+Hooks（兼容 Claude Code 格式）、MCP 客户端（stdio+HTTP）、ACP、HTTP/SSE 服务端、Wails 桌面端，外加 Discord 社区、AtomGit 镜像、velocity 榜单和 10+ 贡献者。**威胁是真实的，且主要来自广度与社区动能，而非单点技术。**

2. **它在我们曾经赖以立身的那条轴上赢了我们。** 同模型（v4-flash）、同价目表、同 grpc-go 实例的 head-to-head 已在机制层确证：dsc **贵 2–4×、缓存命中更低**，整段差距 = 我们独有的 Layer-2「整体 body 驱逐」，而 Reasonix 在同一账号上**零驱逐 / ~97% 命中**。这条「更便宜/更省缓存」的对外宣称**已被我们自己证伪**，必须停止使用（见 [[cache-cost-root-cause]]）。

3. **但仍有继续做的意义——前提是把身份从「最便宜」换成「最严谨/最可验证/最安全/最会路由」。** 这些轴 Reasonix 短期内难以追平，因为它们依赖我们已经建好的**度量文化**（trace schema、cacheparity、可复现实验）。而且缓存差距并非不可挽回：当前有一个**具体、可证伪的开口**——request-shape parity（`stream` vs `chat` 请求形态），可能正是触发 Layer-2 驱逐的根因。这是性价比最高的继续方向。

## 2. 值得我们借鉴的地方

按「投入产出比 × 与我们定位契合度」排序：

1. **双模型 = 独立 session 的纪律（SPEC §3.5）——最该立刻自查。**
   Reasonix 明确写道：「在**同一个会话里**切换模型会破坏前缀、使缓存命中暴跌，所以我们不这么做」——planner 和 executor 各自跑在**独立、各自 cache-stable** 的 session。
   **对我们的含义:** 我们的 `--auto-route`（Flash→Pro 升级）和 Duet pro-validator 如果是在**同一会话内**切换模型/插入第二模型的调用，就可能在制造前缀扰动。**必须验证**：路由升级是否复用同一 prefix epoch，Duet 调用是否走旁路 session。这可能与 Layer-2 现象部分相关，是低成本高价值的一次审计。

2. **CodeGraph 作为一等代码智能。** 用 tree-sitter 符号/调用图取代 embedding 语义搜索——无 embedding 服务、无 API 成本、本地缓存、后台索引。我们只有 `internal/structsearch`（结构搜索），没有完整调用图。**我们自己开发时就在用 codegraph MCP，深知其价值。**

3. **对话检查点/分支 UX（`/rewind /tree /branch /switch`）。** 这是一个**与我们缓存论点天然契合**的特性——从某个 checkpoint 分叉可以保留前缀。我们有 `internal/snapshots/manager.go` 但 TUI 层没有分支命令（grep 仅命中 scrollback）。

4. **Claude Code 兼容即「迁移漏斗」。** 它读 `.claude/skills`、`.mcp.json`（field-for-field 映射）、Claude 风格 hooks/commands。这是一句话定位：「Claude Code 用户零成本切到 DeepSeek」。

5. **多 provider 的 registry 抽象（SPEC §3.1）。** `Provider` 是接口，DeepSeek/MiMo 只是 config 实例，新增 OpenAI 兼容模型 = 改配置而非改代码；原生 Anthropic 是另一个 `kind`。干净、可扩展。

6. **配置/分发打磨：** `reasonix setup` 向导、Homebrew tap、`.env` 自动加载、velocity 榜单式的社区运营。

## 3. 我们真正的优势（必须守住并放大）

这些都经一手核对，是 Reasonix **没有或更弱**的：

1. **可证明的前缀缓存稳定性（机制级，而非口号）。** 我们用**单一 canonical serializer** 同时喂 wire bytes 和 cache fingerprint，二者**构造上不可能背离**，`dsc trace inspect` 显示 `prefixes==1` 可证。Reasonix 在 REASONIX.md/SPEC §3.6 只是**口头要求**「保持 byte-stable」「只在 compaction 时改前缀」，没有暴露任何**可验证**机制。（讽刺但要诚实：它实际命中率更高——见 §5。）

2. **信号驱动的动态路由 + Duet 安全旁路。** Reasonix 的双模型是**静态配置**（`planner_model` 一次设定）；我们的路由按**歧义/反复修复信号动态升级**（`internal/routing/classifier.go` + `clarify.go`），Duet 专门在**破坏性工具调用**上触发 Pro 二次判断。这是更精细的路由故事，它只有 `auto_plan_classifier`（仅用于是否进 plan mode）能对标。

3. **Linux 真 OS 沙箱（Landlock）已落地。** Reasonix 的 bash 沙箱**只有 macOS Seatbelt，Linux 还在 roadmap（SPEC §9）**。我们 macOS sandbox-exec + Linux Landlock + 真 PTY **双平台都有**——这是当下的明确领先点。

4. **度量/可观测性文化（最难被复制的护城河）。** traceschema、traceinspect、cacheparity trace comparator、full-body eviction 检测、`ts_unix_nano`、两账号隔离实验、N=3 可复现 A/B。整本 compendium 就是证据。**Reasonix 断言的东西，我们能证明或证伪。**

5. **自动 reasoning-effort（多语言关键词检测，逐 turn on/off + low/medium/high/max）。** Reasonix 的 effort 是**按 provider 静态**（high/max）；我们按 turn 自动调。

6. **更丰富的代码/Git 工具与编辑引擎:** `git_blame/diff/log/show` 一等工具、`apply_patch`、Levenshtein + replacers + corpus 测试的编辑引擎、`struct_search`、专门的 `repair` 包。

7. **基准严谨度:** `make demo-cache`（live/offline）、tau-bench 移植、cacheparity、swebench-go harness；README 的 94.7% 命中 / 4.5× 是**前缀 A/B 自比**（与 head-to-head 不同轴，未受证伪影响）；tau-bench = 与竞品**能力打平**。

## 4. 可以「直接拿过来 + 改成我们特色」的内容

每条都注明「怎么改成 dsc 特色」（= 套上我们的 trace/rigor/cache 风味）：

| 借鉴项 | 直接拿 | 改成我们的特色 |
|---|---|---|
| **CodeGraph 代码图** | tree-sitter 调用图 + `codegraph_*` 工具面 | 把图查询**纳入前缀缓存预算**——索引结果走 body tail、不动 frozen prefix；用我们的 trace 证明它不引入驱逐。叫法可与 `struct_search` 合并为「cache-aware code intelligence」 |
| **对话分支/检查点** | `/rewind /tree /branch /switch` UX | 强调「分支保留 prefix epoch、命中率不掉」——用 `dsc trace inspect` 展示分叉后 `prefixes==1`。这是别人没有的**可验证分支** |
| **Claude Code 兼容层** | 读 `.claude/skills`、`.mcp.json`、Claude 风格 hooks/commands | 定位语：「从 Claude Code 迁来，且**附带缓存/成本 trace**你在 Claude 里看不到的东西」 |
| **多 provider / 原生 Anthropic kind** | `Provider` 接口 + `kind` 工厂 | 谨慎：保持「DeepSeek 特化」主线，把它做成 **BYOM（bring-your-own-model）旁路**而非平级；对每个 backend 暴露**缓存可观测性矩阵**（哪些 backend 返回 `prompt_cache_hit`，见 head-to-head §8 的 Qianfan 注记） |
| **双模型 = 独立 session** | 这条直接照搬其纪律 | 同上 §2.1——先自查我们的路由/Duet 是否违反，再把「路由不破前缀」做成一条**带 guard test 的不变量**（类比 `TestCompactionPreservesFrozenPrefix`） |
| **GBK/GB18030 编码** | 读写往返保留原编码 | CJK Windows 用户是双方共同市场；低成本真实win |
| **打磨件:** `ask` 选择器、pinned todo、output styles、图片粘贴、setup 向导、Homebrew tap | 逐个抄 | 契合我们 memory 里的「TUI polish phase」 |

## 5. 残酷但必要的诚实：缓存这条轴已经输了 head-to-head

必须在所有对外材料里**钉死**这条边界（[[competitive-vs-reasonix]] / [[cache-cost-root-cause]]）：

- 同 v4-flash、同价目表、同 grpc-go：dsc-best ¥ 0.057/0.013/0.107 vs Reasonix ~0.025/0.007/0.028；**贵 ~2–4×**。
- 整段差距 = Layer-2 **整体 body 驱逐**（命中塌到 ~7,936 token 静态前缀地板，~21K re-miss，呈交替模式）；Reasonix 同账号**零驱逐**。
- 已排除：账号状态、inter-turn 延迟、前缀变异、辅助 LLM 调用、reasoning_content 重放（都做了实验并证伪）。
- **不要再宣称 dsc 更便宜或更省缓存。** 可保留的真实领先：前缀 A/B、tau-bench 打平、预算/路由严谨度、以及「compaction 在前缀缓存 API 上是反模式」这条工程洞见本身。

## 6. 「还有继续做的意义吗？」——分情形的诚实回答

**有意义，但意义是有条件的。** 三种走向：

### A. 高价值续做（推荐）——把身份从「便宜」转向「严谨可验证 + 安全 + 会路由」
- **(必做) request-shape parity 实验**：`request-shape-parity-runbook.md` 已就绪。假设 `stream:true`+`stream_options.include_usage` 的请求形态触发 Layer-2 驱逐，`chat`（非流式）形态可能消除它。Decision Gate 已定义（chat 驱逐数 < stream 即候选；两/三实例零驱逐 + 成本 ≤ Reasonix×1.20 为 strong pass）。**这是唯一可能一举抹平缓存差距的开口，且完全在我们掌控内。**
- **(必做) 路由/Duet 不破前缀自查**（§2.1）+ guard test。
- **(高 ROI) 选择性补广度**：CodeGraph、对话分支、Claude Code 兼容层——每个都「拿来 + 套 trace 特色」。
- **守住并放大**：Linux 沙箱领先、度量文化、信号驱动路由、auto-effort。

### B. 低价值续做（不推荐）——继续在「证明更省缓存」上死磕
- compendium 已在机制层关闭这条路（Layer-2 非我方可控，疑为 DeepSeek 内部 cache TTL 策略）。除非 request-shape 实验 strong pass，否则**不要再投**。

### C. 退出条件（要诚实摆上桌）
- 如果 **(a)** request-shape 实验 fail（chat 不减少驱逐），**且 (b)** 我们既不愿补广度也不愿做社区——那么「特化、更便宜的 DeepSeek agent」这个 wedge 对一个**更快、更广、有社区**的对手是站不住的，应当要么换更锐的 wedge（如「**可审计/可证明缓存与成本的 DeepSeek agent**」面向企业合规/成本敏感场景），要么收缩为我们自用的高严谨工具。

**一句话结论（推断）：** 继续做的意义不在「比 Reasonix 便宜」，而在「成为唯一一个能把缓存、成本、路由、沙箱**逐条证明给你看**的 DeepSeek agent」——这是 Reasonix 的广度打法短期内换不来的，也是我们度量文化已经预付了成本的方向。先做 request-shape 实验定生死，再决定补多少广度。

## 7. 立即可执行清单（按优先级）

1. **跑 request-shape parity 实验**（runbook 已就绪）→ 决定缓存轴生死。
2. **审计 `--auto-route` / Duet 是否在同会话内切模型破前缀** → 若是，按 Reasonix §3.5 改独立 session + 加 guard test。
3. **清理对外宣称**：移除任何「比 Reasonix 更便宜/更省缓存 head-to-head」措辞；改为「可证明前缀稳定 + 可审计成本」。
4. **CodeGraph 集成**（拿来 + cache-aware 特色）。
5. **对话分支/检查点 UX**（拿来 + 可验证 `prefixes==1` 特色）。
6. **Claude Code 兼容层**（读 `.claude/`、`.mcp.json`）作为迁移漏斗。
7. 编码支持、TUI 打磨、Homebrew tap、setup 向导等长尾。

## 附:Reasonix 可被我们利用的弱点

- **headless `run` 子命令有工具派发 bug**（见 `2026-06-02-readonly-headtohead-experiment.md`：`reasonix run` 把有效 markup 当 final 记录、不真正 dispatch；只有交互式 `code`/`acp` 真派发）。CHANGELOG 1.0 未提及修复——**我们的 `-yolo -p` headless 路径是稳的**，可作为 CI/自动化场景的卖点。
